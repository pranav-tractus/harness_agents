What to check next

Based on these results, stakeholders should prioritize model standardization and investigate the root causes of Sonnet 4-5's accuracy issues.

01
Standardize on Sonnet 4-6 for production
Sonnet 4-6 achieved 98.5% field match with reasonable speed (13.5 sec). Deploy this model as the default to maximize accuracy while maintaining acceptable latency.
02
Phase out or limit Sonnet 4-5 usage
Sonnet 4-5's 88.5% field match and 15.3-second runtime make it the worst performer on both dimensions. Remove it from production workflows or restrict to non-critical tasks only.
03
Investigate the 1.5-field average mismatch pattern
Review the specific fields causing mismatches across datasets to identify whether they are edge cases, schema issues, or systemic extraction problems that require prompt refinement.
04
Consider Opus 4-5 as a backup option
Opus 4-5 delivered 95.7% field match at 12.5 seconds—the fastest runtime. If speed becomes critical, this model offers a strong accuracy-latency tradeoff as a secondary choice.
05
Test few-shot prompting to close quality gaps
All models ran with zero few-shot examples. Adding 2-3 examples could lift lower performers (Opus 4-6 at 92.7%, Sonnet 4-5 at 88.5%) closer to the 98.5% benchmark.
06
Monitor improvement and regression rates in production
The datasets showed 44-55% improvement rates with some regressions (7-19 per dataset). Track these metrics in live deployments to catch quality drift early.

How to read these numbers

SUCCESS RATE — Share of runs that finished without a harness or HTTP error. High success means the run was stable; it does not prove the answers matched the reference.

AVG ELAPSED (S) — Average wall time per run in that bucket. Useful for latency comparisons.

AVG MISMATCH / EXPECTED RUN — Average count of fields that differed from the golden JSON when a reference existed. Lower is better.

FIELD MATCH — Fraction of compared fields that matched the golden output across runs in that bucket. Higher is better.
