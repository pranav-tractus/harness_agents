What to check next

Based on these results, consider these next steps to optimize your extraction pipeline.

01
Deploy Sonnet 4-6 for production extraction
With 94% field match and sub-13 second runtime, Sonnet 4-6 offers the best balance of accuracy and speed for most use cases. Pilot it on your highest-value extraction workflows first.
02
Test OpenAI 5.4 for latency-critical paths
Where speed matters more than perfect accuracy—like real-time previews or bulk processing—OpenAI 5.4's 7.7 second runtime and 89% match rate may be sufficient. Run A/B tests to validate the quality trade-off.
03
Investigate the remaining 10% field mismatches
All models averaged 2-3 mismatches per run. Analyze which specific fields fail most often: prompt refinements, better examples, or post-processing rules could push match rates above 95%.
04
Add few-shot examples to improve accuracy
This benchmark used zero-shot prompts. Providing 2-3 examples per task typically improves field match rates by 5-10 percentage points, especially for edge cases the models currently miss.
05
Re-benchmark after schema or prompt changes
If you refine your extraction schema or prompts, run another benchmark to measure impact. Small prompt tweaks can shift model rankings significantly.
06
Monitor Opus 4-6 and Gemini 2.5 Pro for updates
Opus 4-6 (90% match) and Gemini 2.5 Pro (92% match) showed strong accuracy but slower speeds. Track model updates that might improve their latency without sacrificing quality.

How to read these numbers

SUCCESS RATE — Share of runs that finished without a harness or HTTP error. High success means the run was stable; it does not prove the answers matched the reference.

AVG ELAPSED (S) — Average wall time per run in that bucket. Useful for latency comparisons.

AVG MISMATCH / EXPECTED RUN — Average count of fields that differed from the golden JSON when a reference existed. Lower is better.

FIELD MATCH — Fraction of compared fields that matched the golden output across runs in that bucket. Higher is better.
